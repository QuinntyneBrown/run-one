Foundation

Accessibility

WCAG 2.2 AA is the floor. Every interaction works by touch on a phone and by keyboard on a desktop, and colour is never the only carrier of a state.

WCAG 2.2 AAStatus: stable

Overview

These are the commitments every component page documents under Accessibility. A rider may be using a keyboard, a screen reader or a switch; many more are simply out of breath, with wet hands, at arm’s length from the screen. The same rules serve both.

Commitments

  • Contrast. Text 4.5:1; large text, icons, edges and focus 3:1; checked in both themes for every listed pair (1.4.3, 1.4.11).
  • Not by colour alone. “On target” is a word; the chosen option has a filled mark; the strongest effort says so; the countdown says “Go!” (1.4.1).
  • Keyboard. Everything a pointer can do, a keyboard can; a skip link is first; focus is always visible with a 2px ring (2.1.1, 2.4.1, 2.4.7, 2.4.11).
  • Targets. 44 × 44px at the least, 48px mid-ride (2.5.8).
  • Names. Icon-only buttons have an aria-label; the lockup is one image named “Telo Ride 1”; a state a screen reader must know is an attribute (aria-pressed, aria-checked, aria-disabled, aria-busy) and is styled through it (4.1.2).
  • Status. News that does not stop the ride is role="status"; what blocks it is role="alert". Numbers that tick every second are not live regions (4.1.3).
  • Structure. One <h1> per screen (visually hidden on Class Ride), landmarks, real lists and description lists (1.3.1).
  • Motion. Reduced motion is honoured everywhere; Ibiza Flyover is skipped (2.3.3).
  • Zoom and reflow. Sizes in rem; no loss at 200%; no sideways scrolling at 320px (1.4.4, 1.4.10).
  • Data as text. Device names and error strings are rendered as text, never as HTML.

Focus

The ring is 2px of --color-focus-ring, 2px off the control, on :focus-visible. Component pages show it statically with data-state="focus".

Testing

  1. Tab through the screen: order follows the page, the ring is always visible, nothing traps.
  2. Run check_contrast.py after any token change.
  3. Read the screen with a screen reader: the heading, the status lines, the names of icon buttons.
  4. Check 360px and 320px for sideways scrolling, and 200% zoom.
  5. Turn on reduced motion and ride the start and the finish.

The accessibility sweeps in the e2e suite run only when a person asks.
