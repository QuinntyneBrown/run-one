Foundation

Theming

Two themes, dark and light, switched by one attribute. Components read semantic tokens, so a theme is a list of values.

WCAG 2.2 AAStatus: stable
  • Overview
  • Token tiers
  • Both themes
  • Adding a theme
  • Usage
  • Tokens

Overview

The design is dark. The app is dark unless the device asks for light: the served page carries no data-theme, so its first paint follows prefers-color-scheme. Setting data-theme="dark" or "light" on <html>, or on any element, forces a theme for everything inside it.

Token tiers

TierExampleRule
Primitive--palette-signalA raw value. Only theme blocks read it.
Semantic--color-volt-fg, --color-panelA role. Each theme sets it; components read it.
Role alias--color-bg-surface, --color-fg-defaultA second, conventional name for the same role, resolved again on every theme wrapper.
Component--btn-bg, --finish-banner-accentSet on the block, or per theme when the value depends on it; variants change these, not properties.

Adding a theme

  1. Add a [data-theme="name"] block to tokens.css that sets the surface, text, accent and status tokens.
  2. Run check_contrast.py; every pair must pass in the new theme.
  3. Regenerate tokens.json with tokens_to_json.py.
  4. Change no component: if one needs a change, it was reading a primitive.

Usage

  • Never branch on the theme in a component’s CSS. The finish banner’s accent, which must differ by theme, is a themed token.
  • Pictures do not change with the theme; what lies on them uses the on-photo colours in both.
  • tokens.json is the DTCG export for tools; tokens.css is the source.
