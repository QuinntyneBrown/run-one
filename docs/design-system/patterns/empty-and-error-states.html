Pattern

Empty and error states

No screen is ever empty, and an error never ends a ride it does not have to.

WCAG 2.2 AAStatus: stable

Overview

A new rider has no rides, no best and no bike, and still every screen has something to show: Connect Bike is their first screen, The Class simply leaves the record out, and a first Class Done names the number to beat. Errors are sorted by one question: can the ride go on?

When to use what

What is wrongCan the ride go on?Show
No rides yetYesThe Class without the three stats; “Start class”.
No bikeNot yetThe Class with “No bike · Connect” and the start button reading “Connect your bike”.
Wrong browser, or no HTTPSNoThe browser notice on The Class; the blocker on Connect Bike.
Bluetooth off, the chooser blocked or failedNoThe blocker on Connect Bike, with Try again.
The video cannot play, the course cannot be drawnYesAn inline message under the box.
The bike’s resistance cannot be setYesA notice under the bike panel; the stepper reads “—”.
The bike is lost mid-rideAfter reconnectingThe lost-bike alert.
The ride could not be savedIt is overA status under Class Done’s facts; the result stays.
The class cannot be loadedNoOne message over Reload, in The Class’s body.
An address that is not a route—Page not found.

States

Each cause above is a state of its screen, drawn in the mocks: Connect Bike’s bluetooth-off, unsupported-browser, needs-https, chooser-blocked and chooser-failed; The Class’s no-bike, needs-chromium, needs-https, cannot-draw and cannot-load; Class Ride’s video-unavailable, ibiza-unavailable, by-hand and disconnected; Class Done’s first, efforts-none and not-saved.

Responsive behaviour

Messages wrap; actions keep their size. The blocker is the width of its column; the browser notice’s action wraps under its text on a phone.

Accessibility

  • A blocking message is role="alert"; one the ride survives is role="status".
  • The rider sees a plain sentence; the error’s code is for the screen to branch on, never for display.
  • An option that cannot be chosen stays readable and says why.

Content

  • Blocked: what to do, then why. Short of something: what is lost, then what still works.
  • Never blame: “The bike list didn’t open”, not “You cancelled”.
  • Reassure where something might seem lost: “Your rides are safe.” “Your result is above.”
