Form field

The wrapper every input uses: a label above, the control, then a hint or an error below.

WCAG 2.2 AAStatus: stableCore set · no Telo Ride 1 screen uses it yet

Overview

A field keeps a control and its words together and in one order, so every form reads the same.

Where Telo Ride 1 stands: the only typed input is the note in the diagnostic panel, which has its own block. The rider’s app has no forms.

Anatomy

  1. Label14px medium, muted, tied to the control with for.
  2. ControlAny input, 6px under the label.
  3. Hint or error12px, 6px under the control; the error has an icon and takes the hint’s place.

Variants

Label and control.
HTML
<div class="field ds-w-md"><label class="field__label" for="ff2">Note</label><input class="input" id="ff2" type="text" value="bike shows 82 rpm"></div>

<div class="field ds-w-md"><label class="field__label" for="ff3">Note</label><input class="input" id="ff3" type="text" value="bike shows 82 rpm" aria-describedby="ff3-h"><p class="field__hint" id="ff3-h">Say what the bike’s own display shows.</p></div>

Responsive behaviour

It takes the width of its container and has no breakpoints of its own.

Theming

It reads semantic tokens only, so it follows the theme with no rule of its own.

Accessibility

Role and pattern

A <label for> and its control; hint and error are joined with aria-describedby.

Keyboard

The field itself takes no keys; its control does.

Focus

The standard focus ring: 2px --color-focus-ring, 2px off the control.

Labelling

Every control has a visible label. Placeholder text is never the label.

Content

  • Labels are nouns in sentence case, no colon.
  • An error says what to do: “Write a note first.”
