Container

The layout primitives: the app’s full-height shell, its scrolling region, and the centred container.

Overview

Every screen is an .app: a column as tall as the window, with a header that stays and one region that scrolls (.app__scroll) or does not scroll at all. Inside it, .container centres content and gives it the layout margin. See Layout for the grid and the five screens’ form factors.

Anatomy

  1. .appA flex column, 100dvh tall, on --color-ink.
  2. .app__scrollTakes the height left and scrolls on its own.
  3. .containerCentred, at most --layout-container-max wide, with --layout-margin at the sides (16px, 24px from 640px, 32px from 1024px).

Sizes

Widths come from the layout tokens.

States

Layout has no states.

Responsive behaviour

  • The margin steps at 640px and 1024px.
  • Class Ride and Ibiza Flyover do not scroll in a landscape window; The Class does not scroll from 1024px; Connect Bike, Class Done and Page not found scroll when they must.

Theming

Layout only; .app paints the page background.

Accessibility

Role and pattern

No roles of their own: the header, <main> and footer inside them are the landmarks.

Keyboard

It takes no keyboard input: nothing in it can be focused.

Focus

A scrolling region that holds no focusable element gets tabindex="0" so a keyboard can scroll it.

Labelling

None needed.

Contrast

It draws no text or mark of its own; the components inside it carry their own pairs.

Motion

None.

Touch

Nothing is pressed.

Content

Layout carries no words.
